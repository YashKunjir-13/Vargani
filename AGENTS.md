## What this project is

Pauti Pustak is a multi-tenant financial/operational platform for religious, social, and community events (contributor accounts, personalized bills, payment collection, receipts, expenses, volunteers, reporting). Full product context: `ERP-PLANNING/PROJECT-CONTEXT.md`.

## Governance model — do not skip this

This repo uses a gated delivery process defined in `ERP-PLANNING/MASTER-EXECUTION-GUIDE.md`: idea → enterprise plan → plan audit → roadmap → roadmap audit → prompt architecture → **approved task** → completion evidence. In practice: **identify or add the specific `TASK-BACKLOG.csv` row your change belongs to before implementing**, and record real evidence (command output, test results) when done — not a claimed-complete stub. `ERP-PLANNING/phase-completions/*_COMPLETION.md` files are only valid once populated with actual evidence; an unpopulated one explicitly means the phase is not done.

## Non-negotiable rules (from PROJECT-CONTEXT.md — do not violate these)

- Money is stored as integer paise, never floating point.
- Every protected record is tenant-scoped (`organizationId`, plus `eventId` where the record is event-scoped).
- Client-side permission checks never replace backend authorization.
- Confirmed financial records are not deleted or silently modified — corrections use compensating/replacement records that preserve the original.
- Payment confirmation is backend-controlled and idempotent.
- Official bills and receipts are generated by the backend only; client-side PDF generation is preview/draft-only, clearly watermarked as unofficial.
- Every important state change creates an audit event.
- Retried commands, jobs, and webhooks must not duplicate financial effects (idempotency keys throughout).

## Current RBAC model (decided, don't relitigate without a real reason)

Per-organization custom roles — `OrganizationRole` / `Permission` / `RolePermission` (Prisma), with default roles Owner/President/Secretary/Treasurer/Donation Collector/Expense Approver/Auditor/Member, plus organization-defined custom roles. `packages/backend-security` uses `PlatformRole` (`USER`/`SUPER_ADMIN`) for platform-level checks and a `PermissionGuard` + `@RequirePermission(code)` decorator for organization-level authorization, resolved server-side from `roleId` — never a hardcoded role enum, and never trusted from the client or the JWT payload's shape alone.

## Tech baseline

- **Client:** Flutter + Dart, Material 3, Riverpod, go_router, Dio, Freezed/json_serializable, Drift, secure platform storage, English/Marathi/Hindi localization.
- **Backend:** NestJS + TypeScript, PostgreSQL + Prisma, Redis + BullMQ, NATS JetStream, REST/OpenAPI, S3-compatible storage, Handlebars/Puppeteer PDF generation, Razorpay.
- **Monorepo:** pnpm workspaces + Nx. `apps/api` (NestJS), `apps/worker`, `apps/scheduler`, `apps/mobile` (Flutter). `packages/backend-*` for shared backend code, `packages/backend-database` owns the single Prisma schema.
- **Platform:** Docker, Kubernetes, Helm, GitLab CI, OpenTelemetry.
