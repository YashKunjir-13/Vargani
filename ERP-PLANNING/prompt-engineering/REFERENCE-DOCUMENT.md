# Phase 7 Reference — Prompt Engineering Architecture

## Objective

Treat prompts as version-controlled engineering artifacts with ownership, dependencies, context, review, evaluation, and execution evidence.

## Prompt layers

1. Global product and architecture context
2. Domain-specific context
3. Task-specific requirements
4. Live repository context

## Prompt quality requirements

- Clear single objective
- Explicit scope and exclusions
- Exact input and output paths
- Business and security invariants
- Required commands and tests
- Stop conditions
- Definition of Done
- Structured final report

## Governance

Approved prompts are immutable. Changes create a new semantic version. Prompt execution must be linked to a roadmap task and repository commit.
