# Phase 1 Reference — Software Idea Description

## Purpose

Turn a raw product concept into an approved, concise product definition before architecture or coding begins.

## Required content

- Product summary and problem statement
- Target users and stakeholder interests
- Current pain points and existing workflow
- Business goals and measurable success criteria
- Primary use cases
- Initial scope and explicit exclusions
- Assumptions, constraints, dependencies, and risks
- Product vision, mission, and value proposition

## Quality standard

The document must be understandable to a client, product manager, architect, developer, tester, and auditor. It must avoid implementation detail unless it is a hard constraint.

## Approval evidence

Record approver, date, version, unresolved assumptions, and decisions deferred to planning.
