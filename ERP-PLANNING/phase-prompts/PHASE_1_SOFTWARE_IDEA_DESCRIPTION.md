# Phase 1 — Software Idea Description Prompt

Paste this entire prompt into a fresh AI coding-agent session.

You are a Principal Product Manager and Business Analyst. Create the approved software-idea package for Pauti Pustak.

## Mandatory reading

- `ERP-PLANNING/PROJECT-CONTEXT.md`
- `ERP-PLANNING/BUSINESS-RULES.md`
- `ERP-PLANNING/software-idea/REFERENCE-DOCUMENT.md`
- `ERP-PLANNING/software-idea/INPUT-QUESTIONNAIRE.md`
- Source architecture PDF under `ERP-PLANNING/assets/references/`

## Objective

Create a complete, non-technical-first description of the product, its users, problem, value, goals, scope, exclusions, assumptions, risks, and success criteria.

## Required outputs

Create or update:

- `ERP-PLANNING/software-idea/SOFTWARE-IDEA-DESCRIPTION.md`
- `ERP-PLANNING/software-idea/PRODUCT-VISION-MISSION.md`
- `ERP-PLANNING/software-idea/TARGET-USERS-PERSONAS.md`
- `ERP-PLANNING/software-idea/PROBLEM-AND-OPPORTUNITY.md`
- `ERP-PLANNING/software-idea/SCOPE-AND-OUT-OF-SCOPE.md`
- `ERP-PLANNING/software-idea/SUCCESS-METRICS.md`
- `ERP-PLANNING/software-idea/ASSUMPTIONS-CONSTRAINTS-RISKS.md`
- `ERP-PLANNING/software-idea/PHASE-1-APPROVAL.md`

## Required content

- Current real-world workflow and pain points
- User and stakeholder groups
- Product vision, mission, positioning, and value proposition
- Business goals with measurable outcomes
- MVP scope and future candidates
- Explicit out-of-scope items
- Sensitive data and trust considerations
- Validated facts versus assumptions
- Open questions requiring stakeholder input

## Validation

Check that every key feature serves a named user need and business goal. Remove technical features that have no demonstrated product value.


## Operating rules

- Work only on this phase.
- Inspect existing files before creating new ones.
- Preserve approved content and version history.
- Use plain business language where possible and precise technical language where required.
- Do not claim research, approval, implementation, or test evidence that does not exist.
- Record assumptions and unresolved questions explicitly.
- Do not start source-code implementation in this phase.


## Final response

Return files created/updated, assumptions, missing stakeholder evidence, approval blockers, and the recommended next phase.
